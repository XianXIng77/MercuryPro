# 操作审计覆盖检查（2026-09-05）

## 本次修复

- 原先中间件排除整个 `/api/auth/*`，角色授权和用户授权完全漏记。现为全部写接口提供兜底，手工记录通过请求标记去重。
- 个人资料与密码更新归属“个人中心”，补齐参数校验、会话失效、头像校验、新旧密码相同等失败分支；前端筛选增加“修改个人资料”“修改密码”。
- 角色授权与用户授权归属“权限中心”，记录操作人、目标、变更前后的角色/菜单/权限，以及成功或失败。成功授权修改标记为高风险，不记录用户密码等字段。
- 新增 GET `/api/download`、`/api/solver/detect`、`/api/proxy/detect` 的审计。`/api/download/history` 仅查询历史索引，不是导出文件。
- 兼容 `/api/grok/*` 旧路径，统一模块归类；原来大量归属“工作台”的操作现在归入邀请码管理、系统配置、注册任务、注册邮箱、账号导入等模块。
- 中间件在鉴权守卫外执行，HTTP 401/403/422、辅助服务 503、未处理异常 500 都能记录。
- 通用日志仅使用方法、脱敏路径和 HTTP 状态，不读取请求体或查询参数；隐藏公开邮箱访问令牌和邀请码路径。写入失败输出服务端错误日志，不把已完成的业务操作变成失败响应。

## 扫描范围与结果

扫描 `app.py` 以及实际挂载的认证、微软邮箱、AI、诊断日志、操作审计和浏览器调试路由。

- 当前共有 54 个状态变更 HTTP 接口（POST 38、PUT 7、PATCH 1、DELETE 8），全部纳入通用审计；回归测试会检查这些路由的覆盖和模块归类。
- 39 个 GET 路由中，对上述 3 个显式执行/导出操作增加审计。普通列表、详情、轮询、健康检查、静态资源仍不记录，以免自动刷新刷屏。
- 另有 1 个 VNC WebSocket，不经过 HTTP 审计中间件。
